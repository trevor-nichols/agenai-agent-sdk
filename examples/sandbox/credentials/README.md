# Explicit credential recipes and direct CLI ownership

These example-only modules compose the public sandbox API. They do not install a provider, discover a login, inherit the controller environment or attest a workload image. Each provider directory owns its closed credential mapping, exact native version, configuration and candidate network destinations. The caller must independently verify its prepared image, Linux platform, executable and complete launcher/configuration closure before constructing that provider recipe.

`captureSandboxApiKey` accepts exactly `{ kind: 'api_key', value }`. Values must be nonempty well-formed Unicode, contain no NUL/CR/LF and occupy at most 8,192 UTF-8 bytes. Capture preserves spaces and bytes without normalization. It does not prove the key is valid. Guest executable paths must be canonical absolute paths. Tasks are bounded to 64 KiB of well-formed NUL-free UTF-8. Provider recipes accept their own closed input; an arbitrary environment, flag list or credential fallback is unavailable.

Each recipe derives its native egress from the borrowed sandbox's effective network policy. Under `restricted_https` the workload has no direct route, so `sandboxNativeEgress` first requires every destination the recipe declares to be admitted, failing before reservation otherwise. It then points the native client at the Docker relay `http://127.0.0.1:3128` with upper- and lower-case proxy variables and keeps loopback direct through `NO_PROXY`. Native clients use their own proxy support; Node's built-in environment proxy is not enabled, because Cursor's instrumentation adds tracing headers to its CONNECT requests that the relay rejects. Isolated and outbound sandboxes receive no proxy variables. Whether a given native client honors these variables is native-campaign evidence, not a promise of this helper.

`runSandboxCli(reservation, { stdin, signal? })` consumes a single existing reservation. Select `stdin: 'none'` when the native task is already in argv, or `{ kind: 'utf8', text }` for Codex's stdin task. It writes the selected input once, closes stdin, owns the sole stdout reader and separately drains stderr. It discards all native output instead of retaining raw provider diagnostics. Stdout is limited to 8 MiB and 4,096 newline bytes; stderr is limited to 1 MiB. The sandbox's independent input/output/deadline policy still applies.

The result contains the original leader receipt and observed stdout/stderr byte counts. Numeric nonzero exits remain numeric nonzero exits. An exit of zero establishes neither authentication nor the requested tool effect; independently inspect the selected exported artifact and the campaign's native observations. The runner stops the whole sandbox immediately after observing the leader, then joins its entered stream work. Descendants can hold pipes open, so EOF is not a precondition for dispatching that stop. Counts describe bytes consumed before shutdown, not a promise to preserve a complete native transcript.

Cancellation and stream/limit failures also dispatch whole-sandbox stop. `SandboxCliRunError` has a fixed message, a safe failure code and an observed receipt when available; it does not retain an abort reason or raw stream error. If physical cleanup fails, `cleanupFailure` retains the original cleanup error and its original owner without serializing that error in JSON. Keep the error and original sandbox reservation, and explicitly call `retryCleanup()` before final export/destruction. This joins already-entered work without another process start, credential delivery or native task. The caller always owns final storage destruction. No cleanup failure authorizes replay.

Provider preflight is a separate plain object and can be serialized independently from launch inputs and cleanup owners. It describes a selected recipe and unresolved native evidence. Never serialize credential inputs, source bytes, environment values, raw streams or cleanup error causes. The trusted controller, native workload and Engine can see a selected key; JavaScript strings and native environment copies have no zeroization guarantee.

The memory tests use the real public backend/process boundary. Codex's separate source tests read only freshly written private synthetic files. These tests prove mapping, stream ownership and cleanup behavior; native account validity, billing and platform admission belong to the explicit qualification campaign.
